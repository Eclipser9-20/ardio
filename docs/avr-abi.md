# The AVR ABI ardio targets

ardio's compiler follows avr-gcc's ABI exactly. That is a deliberate choice: it
means ardio's output and avr-gcc's output describe the same machine, so code
generated by one can call code generated by the other, and anything learned
about one applies to the other.

This document is the reference the code generator is written against.

## Registers

| Register | Role |
|---|---|
| `r0` | Scratch. Callers must assume it is destroyed. Not allocatable. |
| `r1` | **Permanently zero.** Any instruction that disturbs it (notably `mul`) must clear it again immediately. Not allocatable. |
| `r2`–`r17` | Call-saved. A function using these must restore them. |
| `r18`–`r27` | Call-clobbered. Free for scratch use. |
| `r28`:`r29` | The frame pointer, `Y`. Call-saved. |
| `r30`:`r31` | `Z`. Call-clobbered. The only pointer usable with `lpm`. |
| `X` = `r26`:`r27`, `Y` = `r28`:`r29`, `Z` = `r30`:`r31` | The three pointer pairs. Only `Y` and `Z` have a displacement form (`ldd`/`std`). |

The T flag in `SREG` is also call-clobbered and, like `r0`, is used as a scratch
bit by generated code.

## Passing arguments

Arguments are allocated from register number **26 downwards**:

1. Round the argument's size up to an even number of bytes.
2. Subtract that from the current register number.
3. If the result is at least `r8`, the argument's low byte goes there and its
   remaining bytes in increasing registers.
4. Otherwise this argument and **every argument after it** goes on the stack.

Worked through, for the common cases:

| Signature | Where the arguments land |
|---|---|
| `f(int)` | `r24:r25` |
| `f(int, int)` | `r24:r25`, `r22:r23` |
| `f(int, int, int)` | `r24:r25`, `r22:r23`, `r20:r21` |
| `f(char)` | `r24` (rounded to 2 bytes, so `r25` is skipped) |
| `f(char, int)` | `r24`, then `r22:r23` |
| `f(long)` | `r22`–`r25` |

Note the consequences: arguments are **not** promoted to a wider type, and an
argument is passed either wholly in registers or wholly in memory — never split.
A method's implicit `this` is simply the first argument, so it arrives in
`r24:r25` and pushes the declared parameters down.

## Returning values

Return values use the same registers as if the value were the first argument:

| Size | Returned in |
|---|---|
| 1 byte | `r24` |
| 2 bytes | `r24:r25` |
| 4 bytes | `r22`–`r25` |
| 5–8 bytes | `r18`–`r25` |
| larger | In memory: the caller allocates space and passes its address as an implicit first argument |

## The frame

`Y` points at the frame. Locals are addressed as `Y+q`, and because `ldd`/`std`
encode only a 6-bit displacement, **`q` cannot exceed 63** — a function needing
more local storage than that must be rejected rather than silently miscompiled.

The prologue saves the caller's `Y`, copies the stack pointer into it, and
opens the frame. Updating the 16-bit stack pointer is not atomic, so interrupts
are disabled across the two halves:

```
    push r28
    push r29
    in   r28, 0x3D        ; SPL
    in   r29, 0x3E        ; SPH
    sbiw r28, <frame>
    in   r0, 0x3F         ; save SREG
    cli
    out  0x3E, r29        ; SPH
    out  0x3F, r0         ; restore SREG (re-enabling interrupts if they were on)
    out  0x3D, r28        ; SPL
```

The epilogue reverses it exactly, then `pop r29`, `pop r28`, `ret`.

## Library helpers

avr-gcc does not inline division, 32-bit multiplication, or wide shifts. It
calls helpers from libgcc, and several of them use a **restricted calling
convention that clobbers far fewer registers than a normal call** — which is
precisely why the compiler can keep values live across them.

`ardio` implements API-compatible equivalents in `runtime/`, using the same
names and register contracts so the two are interchangeable.

Machine mode suffixes: `QI` = 8-bit, `HI` = 16-bit, `SI` = 32-bit.

| Helper | Operation | Clobbers |
|---|---|---|
| `__udivmodqi4` | `r24 = r24 / r22`, `r25 = r24 % r22` (unsigned) | `r23` |
| `__divmodqi4` | as above, signed | `r23`, `r0`, T |
| `__udivmodhi4` | `r22:r23 = r24:r25 / r22:r23`, `r24:r25 = r24:r25 % r22:r23` (unsigned) | `r21`, `r26:r27` |
| `__divmodhi4` | as above, signed | `r21`, `r26:r27`, `r0`, T |
| `__umulhisi3` | `r22..r25 = r26:r27 * r18:r19` (unsigned) | `r0` |
| `__mulhisi3` | as above, signed | `r0` |

Two details worth internalising, because getting them wrong produces code that
looks right and computes garbage:

- **The divide helpers return quotient and remainder in swapped positions.**
  `__udivmodhi4` takes its dividend in `r24:r25` and leaves the *quotient* in
  `r22:r23`, with the *remainder* back in `r24:r25`. A `/` therefore ends with
  the answer in `r22:r23`, and a `%` in `r24:r25`.
- **`mul` destroys `r1`.** Every multiply sequence must end by clearing `r1`
  again, or every later instruction that relies on the zero register silently
  computes with rubbish.

## What ardio does not implement

- Floating point. avr-gcc emulates it via libgcc (and `libf7` for 64-bit); ardio
  has no float support at all, and the type system has no float kind.
- The `__flash` / `__memx` address spaces and the `progmem` attribute.
- Interrupt attributes (`interrupt`, `signal`, `naked`, `OS_main`).
- 24-bit `__int24` / `__uint24`.
- Varargs, which avr-gcc passes entirely on the stack.
